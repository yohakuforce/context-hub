# Context-Hub v0.2.0 — Bring Your Own Context

Released: 2026-05-20

v0.1.0 connected Context-Hub to the systems where your team already chats and tracks work — Slack, Backlog, Redmine. v0.2.0 closes the loop on **everything else**: meeting notes, ad-hoc memos, contract PDFs, Gmail threads, and any other text that lives outside those source systems.

## Highlights

### Drop files into a folder, they show up in your AI agent

Set `CH_INBOX_DIR=~/.context-hub/inbox` in `.env`, then save Markdown into `inbox/meeting/`, `inbox/file/`, or `inbox/email/`. A background watcher picks them up within `CH_INBOX_POLL_SECONDS` (default 60). Editing a file upserts the prior document. Unchanged files are skipped — no wasted embedding cost.

No commands, no API. Drop and go.

```
~/.context-hub/inbox/
  meeting/
    2026-05-20-weekly.md      ← drop here
    2026/05/20-detail.md      ← nested subdirs are fine
  file/product-spec.md
  email/saved-thread.txt
```

### Upload contracts, memos, and reports

```bash
curl -X POST http://127.0.0.1:8000/api/v1/documents/upload \
  -H "X-Api-Key: $CONTEXT_HUB_API_KEY" \
  -F "project_id=$PROJECT_ID" \
  -F "source_type=file" \
  -F "file=@./contract.pdf"
```

`.md`, `.txt`, `.pdf`, `.docx` are supported. PDF and DOCX text extraction lives behind the new `[documents]` extra:

```bash
pip install 'yohakuforce-context-hub[documents]'
```

10 MiB max per file. Scanned PDFs without OCR are rejected with a clear error.

### Gmail ingest with label-based opt-in

Tag emails in Gmail with the `context-hub` label and they sync into the store. Private mail without the label stays out.

```bash
pip install 'yohakuforce-context-hub[gmail]'
# Configure GMAIL_CREDENTIALS_FILE + GMAIL_TOKEN_FILE in .env
context-hub ingest gmail --mode live   # opens browser for one-time OAuth consent
```

`GMAIL_QUERY` defaults to `label:context-hub`. Override with any Gmail search syntax for broader filters (`from:client@example.com`, `label:project-a newer_than:30d`, etc.).

### JSON API for one-off ingests

Already have the text in hand? Skip the file system:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/documents \
  -H "X-Api-Key: $CONTEXT_HUB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "proj-001",
    "source_type": "meeting",
    "title": "Kickoff",
    "text": "Decision: ship plan A.",
    "external_id": "kickoff-2026-05-20"
  }'
```

Same `(project_id, source_type, external_id)` upsert semantics as the file watcher.

### `context-hub ingest inbox` for an immediate scan

If you don't want to wait 60 seconds:

```bash
context-hub ingest inbox
# Inbox scan complete. ingested=3 updated=1 skipped=12 errors=0
```

## What's the operating model?

Treat **one Context-Hub instance = one project**. It's cheap (one Python process, one SQLite file) and gives you an absolute isolation guarantee: nothing from client A's mail ever lands in client B's index.

Each instance gets its own `.env`, its own `CH_INBOX_DIR`, its own `GMAIL_QUERY`, and its own port. Run them in parallel under launchd / systemd / pm2.

See [`docs/usage-guide.md`](../usage-guide.md) for the full walkthrough.

## Under the hood

- Manual ingest reuses the same `DocumentRepository` and `EmbeddingProvider` as the Slack/Backlog/Redmine path — hybrid search just works across all five inputs without any new query code.
- Mock fixtures (used by `INGEST_MODE=mock`) are now bundled with the wheel at `context_hub/_fixtures/`. `pipx install yohakuforce-context-hub` followed by `context-hub ingest gmail --mode mock` now works out of the box.
- 47 new tests; total suite is 671 passing.

## Upgrading from v0.1.0

```bash
pip install --upgrade yohakuforce-context-hub
# Optional extras
pip install 'yohakuforce-context-hub[documents,gmail]'
```

- No DB migrations required. Existing SQLite / PostgreSQL files keep working.
- New environment variables are all optional. Existing `.env` files continue to work unchanged.
- The MCP protocol version is unchanged (`2024-11-05`); Claude Desktop / Claude Code clients keep working without reconfiguration.

## What's not yet in v0.2.0

- **Whisper audio transcription** for voice meeting notes — planned for a future release.
- **Full authentication system** (bcrypt + ConsumerRepository) — still on the roadmap. The current `DEV_API_KEY` model is unchanged.
- **`fsevents` / `watchdog` instant inbox detection** — the 60-second polling cadence remains the default. Sufficient for meeting notes and memos; if you need lower latency, file an issue.
- **OCR for scanned PDFs** — convert to text-layer PDF before uploading.
